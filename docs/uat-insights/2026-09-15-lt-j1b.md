## 3. Methodology lessons

- **A single-journey re-run is the cheap way to settle a driver artefact.** Ten steps for each of five Characters turned a run-wide theme ("the level check disappears for half the Characters") into a measured placement table. The method works. Its schema miss is that the closure lives only in `VERIFY.md` prose: neither this run nor the parent carries the five refuted rows forward as rows (they are `n-a` in the parent). The skill's carry-forward rule asks for that.
- **Accuracy and acceptance are separate outcomes, and this run shows it cleanly:** four exact placements against one pass verdict. A placement metric alone would have called the check good.
- **A possible upward lean that the method cannot separate.** All near results here and in the parent sit one band above the true band, but the Character model writes the answers the judge grades. A test of the judge needs fixed-text learner answers (LG-18). **Proposal (overlay, not applied):** a placement journey variant with scripted answers per band.
- **Time saved is 0 for all five, four of them with low confidence.** Every voice says it cannot judge the waits from a transcript. The driver records call timings but not what the learner waited through, so "worth the wait" stays unmeasurable at LT.

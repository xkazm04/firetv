# V3: surface laboratory design and research

2026-10-01, design before implementation. V3 proceeds while the owner chooses V1; it cannot select the final world style for V4.

## Research, checked on 2026-10-01

- [libGDX SpriteBatch](https://libgdx.com/wiki/graphics/2d/spritebatch-textureregions-and-sprites): texture changes flush batches; an opaque background can disable blending. Experiment: one repeated ground draw and a batched spline ribbon, then seeded atlas decals. Count actual submissions, not Java draw invocations.
- [libGDX texture packing](https://libgdx.com/wiki/tools/texture-packer): shared texture storage reduces texture binds. Experiment: keep decals and depth props on a small shared experimental page with at least 6px cell insets, separate repeating ground pages. Production packing still requires the existing extruded-margin gate; this page is a lab input.
- [libGDX framebuffer objects](https://libgdx.com/wiki/graphics/opengl-utils/frame-buffer-objects): offscreen targets render to a texture, and orientation/viewport restoration matter. Experiment: bake a 1024-square course image and compare it with the same live geometry; a persistent 512-square wear buffer tests incremental skid accumulation. These allocations are counted, never described as free.
- [libGDX particles](https://libgdx.com/wiki/graphics/2d/2d-particleeffects): texture and blend changes can flush batches. Experiment: bounded dust quads sharing one page, ordinary alpha blend and no extra full-screen blur pass.
- [Arm mobile performance analysis](https://developer.arm.com/community/arm-community-blogs/b/mobile-graphics-and-gaming-blog/posts/finding-and-fixing-hidden-performance-problems-in-mobile-games-with-arm-performance-studio): bandwidth, transparent overdraw and post-processing matter on mobile; passive cooling makes hardware measurement necessary. Experiment: isolate every layer and report declared texture bytes, submitted geometry coverage and measured frame intervals. No desktop timing is substituted for Stick timing.
- [Histogram-preserving randomized tiling demo](https://benedikt-bitterli.me/histogram-tiling/) and [researchers' edge-blending demo](https://unity-grenoble.github.io/website/demo/2020/10/16/demo-histogram-preserving-blend-make-tileable.html): stochastic blending can conceal repetition, especially for non-periodic natural material. We test a simpler low-frequency multiply field first. We do **not** claim it implements histogram-preserving synthesis or repairs bad source seams. Seam/repetition gates remain unchanged.
- [Android game tracing](https://developer.android.com/games/optimize): CPU submission and GPU execution are different, and presentation pacing can hide spare capacity. Record wall-clock frame intervals and CPU submission duration separately. A 16.7 ms interval does not prove a feature costs zero GPU time; isolated scene results do not certify full-game soak.

Registry notes were read only: media-generation laws, style-block-restated-every-call, two-block-style-and-action, gate-before-every-credit-spend; game-production laws, wrap-around-edge-diff, seam-threshold-calibration, atlas-packing-and-bleed-margins, sampler-hard-and-soft-caps, feature-cost-with-a-cheaper-swap and seed-determinism-contract. Their consequences here: immutable source hashes, unchanged thresholds, rendered A/B evidence, recorded seed/algorithm/parameters, explicit cheaper alternatives and no pass for absent hardware evidence. Grok tile guidance moved into `game-assets/tilesets.md` in the installed bundle.

## Experiment contract

Use a separate libGDX application, `dev.deathride.artlab`, sharing its renderer between Android and desktop. It is a faithful rendering mock: 1080p, orthographic world, six rotating car sprites, repeating linear-filtered 256-square materials, spline road, batched alpha sprites. It excludes simulation, networking, menus and the production renderer's other allocations. Do not change game physics, dimensions or camera tuning. Proof ground inputs from three style cards are review-only and carry their source gate status.

Keep a fixed seed, path and car positions for A/B screenshots; animate the same path for timed runs. Isolate: painted material substitution; macro multiply at four times tile period; seeded cracks/oil/skids; course bake; edge ink/shoulder/barrier treatment; shader grade plus bounded dust; overlapping tall props/shadows; persistent low-resolution wear; palette quantisation/grain; lower-detail ground/value separation. Also show a combined stack. Measure interactions rather than adding independent deltas and calling that measured.

For each mode, report resident RGBA bytes (including render targets), actual SpriteBatch flushes, approximate submitted pixel area as an overdraw proxy, PSS from `dumpsys meminfo`, p50/p95/max frame intervals and CPU submission time. Retain raw timing samples and screenshots. Warm before sampling; repeat baseline around variants to expose drift. Short isolated runs are not the 15-minute integrated soak.

Scan the local /24 for TCP 5555, identify the device, install only the hardcoded lab package. The integration package is never replaced, force-stopped or cleared. Check foreground ownership, refuse to take a running integration race, and abort if another activity takes foreground during a lab window. Use a common-worktree device lease; restore the prior activity only while the lab still owns foreground. Build and export boards without hardware if busy/offline; label device costs not measured rather than inferred.

The existing declared production art budget remains 30.75 MiB. Lab residency is a separate experiment. Any proposed production addition must fit the 1.25 MiB headroom or explicitly replace an existing allocation. Never add a 4 MiB bake and quietly claim the old budget. V4 requires owner style and stack choice, then bundle validation and hardware measurement.

## Integration boundary

The art branch's `deathride/game/src/main/kotlin/dev/deathride/game/TrackScene.kt` owns a reusable scenery FBO and builds deterministic geometry in bounded slices. Its current 3072-square RGBA target is 36 MiB outside the declared 30.75 MiB art allocation. The lab baseline is a newly constructed comparison course using delivered V1 tiles, not a capture or timing of that full game. Its 1024 bake cannot simply be added to the game and described as a memory saving. Replacing the existing target could change total residency substantially, but needs explicit integration design, quality checks and a new full-game measurement.

Likewise, the candidate's 31.8125 MiB calculation is conservative **art** residency including a new 1 MiB detail page. It does not cap whole-process PSS. A production implementation should first repack reusable decals into existing pages, retain seeded placement independent of simulation randomness, and batch atlas sprites by texture where ordering allows. Repacking and different car batching remain unmeasured savings. Narrow edge bands are the follow-up experiment below. Combined runs measure their actual interactions; individual deltas are not summed into a claimed frame rate.

## Measured revision decision

The integration execution granted a window after its soak, recorded in `art/surface-lab/device/handoff.json`. The clean forward and reverse passes preserve the integration installation and restore its prior activity. Both show the restrained stack missing nominal 16.7 ms cadence: p50 17.65 and 17.28 ms. Its 32 decals, 28 dust quads and three full-width hidden edge layers are therefore **not** an accepted default. The all-layer stack is slower again and also loses visual clarity. Neither failure is tuned away in the evidence.

One additional experiment follows that finding: mode 14 keeps macro colour variation, ground grading and edge colours, but draws only the three visible narrow edge bands, halves decals to 16, and caps dust at eight quads. This removes submitted coverage rather than reducing resolution, car scale, sample count or acceptance thresholds. The initial renderer is archived under `tools/art/surface-lab/revisions/v3-1/SurfaceLab.java`. The new APK remeasures painted and restrained controls alongside the efficient variant, twice in opposite orders. Only matched APK/control pairs enter its delta. It receives a separate handoff window and must pass the same evidence checks before any measured recommendation.

The original fourteen experiments completed 28 clean measurements in forward/reverse order, followed by six appearance runs across the two other ground proofs. Median-of-run statistics: painted control 16.70/17.97 ms p50/p95; edge treatment 16.68/17.83 ms, with two more flushes and 2.39x submitted-area coverage; all layers 25.14/31.15 ms; restrained stack 17.46/23.69 ms. The 1024 course bake has 42.51 ms median startup completion and adds 4 MiB; it saves four draws against the matched live control but exceeds current art headroom and softens the scene. The nominal frame target and 32 MiB art allocation are unchanged. Tiny negative deltas around display cadence are noise, not a performance win. The report retains the actual p50/p95/max samples, CPU submission, synchronous completion, PSS and geometry costs for each mode.

The narrow-band follow-up cut submitted coverage from 2.479x to 1.477x, but its two Stick p50 values were 17.85 and 17.73 ms. Rebuilding twice as many edge quads raised CPU submission cost; lower coverage alone did not improve frame cadence. It is also cut. The final experiment caches the same road and edge vertices (201,600 bytes of float payload), submits them in bulk, and requires exact screenshot equality against dynamic geometry. Its first desktop trial caught an integer colour-overload error; float colour packing fixed it before hardware, and the corrected desktop images are byte-identical after RGB decoding. The failed check and correction are retained in reports.

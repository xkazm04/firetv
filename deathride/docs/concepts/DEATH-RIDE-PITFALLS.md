# Spike pitfalls ? 2026-09-30

- **Compile SDK:** the first scaffold failed because libGDX 1.13.5 brings AndroidX core 1.15, requiring compile SDK 35+. Use the available platform 36; keep minSdk 28 and targetSdk 34. Evidence: build logs. This does not establish compatibility on a device.
- **Native userland:** 64-bit silicon can still run a 32-bit Android userland. Package arm64-v8a, armeabi-v7a and x86_64 and inspect the built APK, not only the dependency declarations. Evidence: `tools/verify_apk.py`.
- **Port lifecycle:** a suspended app must release 8765, and asynchronous bind failures must not escape to the process. Preflight the socket, retry ten times at 300 ms, catch engine failures, stop on pause, rebind on resume. Tokens survive activity pause; process death creates a fresh lobby. Evidence: `LinkTest` tests occupied port and suspend/rebind/reconnect.
- **Controller clock:** raw phone timestamps and TV monotonic time have different origins. Correct by ping/pong midpoint before rejecting age; report whether sync occurred. Keep receive-time fallback explicit. Evidence: two-client protocol probe.
- **Windows probe timers:** a naive 33 ms interval delivered about 22.5 Hz here. The probe now schedules against its next absolute due time and reports actual Hz; final runs achieved approximately 30 Hz. Browser timers and real phones still need device measurement.
- **Plain HTTP wake lock:** Chromium did not expose the Screen Wake Lock API on the LAN origin. Feature detection and rejection handling are required. Fullscreen is optional; driving does not depend on either feature. Offline installation is not promised. Evidence: LAN browser result.
- **HUD churn:** cached font layouts still rebuild strings and glyph runs. Fixed glyph vertex buffers and a reused character builder remove that recurring layout allocation. The desktop audit includes transitions and its diagnostic screenshots; the pure simulation has a separate zero-allocation gate.
- **Desktop keyboard testing:** an OS Robot attempt did not reach the game in this shared desktop session. The final harness injects into this instance's GLFW callback and exercises both queued events and polled key state; it cannot certify a physical keyboard or a Fire remote.
- **Scope of truth:** desktop GL, localhost RTT and JVM simulations cannot establish Stick thermal performance, Wi-Fi delay or perceived feel. Gate G0 stays closed until those are measured by the owner.

## 3. Methodology lessons

- **The first claude-CLI LT run reproduced three codex-era gaps.** The same Character on the same journey, with a different engine for every role, failed on the same three points. That makes these three gaps unlikely to be codex artefacts. The converse does not hold: a gap that does not reappear has not closed (§1).
- **The ledger cannot see a recurrence that a plain run finds.** Every row here carries `recurrence: 1`, and `OPEN.md` reports `recurring 0`. Meanwhile it lists the three `-lt-j1b` rows as "unasked since 2026-10-09-lt", although this run raised all three again. The ledger links rows only by `recurs` (`uat/driver/ledger.cjs:15-18`), and only a recertify shows the judge the pair's open rows. A plain run of a pair with open gaps starts blind, so the drain linked them by hand. **Proposal (overlay, not applied):** a plain run passes its pair's open rows to the judge in `prior[]`, as recertify does, so a returning gap is stamped `recurs` at run time.
- **Two of the synthesis's fields render as raw JSON.** `SUMMARY.md`'s *Panel verdict* and *Value ledger* print `["…"]`: a one-element array, written unformatted. This is cosmetic, but the SUMMARY is what the owner reads. **Proposal (driver, not applied):** join string arrays in the SUMMARY writer.
- **One Character cannot rank.** The synthesis says so itself ("no cross-Character pattern can be claimed"), and its ranking rests on reachability alone. The drain's ranking leans on the 09-15 convergence instead. A claude-CLI run of the full cast on J1 would test whether the upward lean (LG-10, LG-18) holds across Characters. Time saved (10 minutes, low) is not quoted.
- **The judge read the whole screen.** With `judgeScreenCap` at 8,000 characters (the 900-character cap behind LG-3 is gone), no row here is a driver artefact. The judge also recorded where it disagreed with the code's verdicts (*Disagreements*), and that line carried LG-10's strongest evidence.
